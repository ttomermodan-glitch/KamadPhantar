## העלאה ל-GitHub ול-Render

1. חלצו את ה-ZIP. היכנסו לתיקייה `news404-server` והעלו **את תוכנה** לשורש מאגר GitHub שבו האתר שלכם נמצא. החליפו את `server.js`, `public/index.html`, `package.json` ו-`bank.json` ביחד. אין להעלות את `index.html` לתיקייה הראשית.
2. ב-Render בחרו Web Service המחובר למאגר ולענף `main`.
3. Build Command: `npm install`; Start Command: `npm start`.
4. מומלץ מאוד להגדיר משתנה סביבה `ADMIN_PASSWORD` לסיסמה פרטית. סיסמת ברירת המחדל `kamadP` נועדה לבדיקה בלבד.
5. בחרו Manual Deploy -> Deploy latest commit (או Clear build cache & deploy אם נדרש).
6. לאחר פריסה, בדקו בלוח האדמין **ממשק** ו-**שרת**: בשניהם חייב להופיע `2026.11.11-concepts.4`. אין לערבב את הקבצים עם גרסה 7 או 8 של המשחק הישן.

## שלושת הקונספטים

1. מוצר אבסורדי שישנה את החיים בקמ״ד.
2. תוכנית ריאליטי שמתרחשת בקמ״ד.
3. ההקפצה המופרכת ביותר שאפשר להמציא. נשארת רעיון בדיוני, לא ביצוע בפועל.

כל קבוצה מגישה **שם קונספט והסבר** אחד לכל סבב. ההגשה האחרונה של אותה קבוצה, לפני סיום חמש הדקות, היא הקובעת.

## הצבעות וניקוד

- שלושת הרעיונות נחשפים בזה אחר זה על המקרן בלבד. ההצבעה נפתחת **רק אחרי** שכל השלוש הוצגו.
- החניכים מדרגים מ-1 עד 5 את שתי הקבוצות האחרות, ולא את הקבוצה שלהם.
- המפקדים יכולים לדרג כבר במהלך החשיפה, ולאחר מכן לאורך דקת ההצבעה. לכל כרטיסייה חובה לכתוב **ציון 1 עד 5 ונימוק קצר**.
- ציון סבב = 70% ממוצע ציוני הסגל + 30% ממוצע הקהל. כדי לצמצם יתרון של קבוצות גדולות יותר, ממוצע הקהל מחושב קודם בנפרד לפי קבוצת המצביעים, ורק אחר כך ממוצעים את שני החלקים.
- אם חסר דירוג באחד משני הערוצים, הממוצע בערוץ השני משמש לבדו; אם אין דירוגים כלל, הציון הוא 0. קבוצה שלא הגישה מקבלת 0 לאותו סבב.
- בסיום המשחק מחברים את שלושת ציוני הסבבים, מתוך 15. אם יש תיקו במקום הראשון הוא יוצג כתיקו.
- הנימוקים של הסגל נשמרים לכל הסבבים, נימוק אחד נחשף לצד כל קבוצה בשלב התוצאות, ועוד נימוקים מוצגים בסיום.

- אפשר לנעול הצטרפות חדשה. כניסה חוזרת של משתתף שכבר מחובר אינה ננעלת בגלל נעילת כניסה.
- המשתתפים שולחים דופק כל כ-5 שניות. מי שנעלם מהרשת לא ייספר כמחובר אחרי חלון סבילות של כ-11 שניות.
