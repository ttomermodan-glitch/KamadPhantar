## הרעיון

מחלקים את החניכים באקראי לשלוש קבוצות מאוזנות. כל קבוצה מקבלת **חמש דקות** להכין הצעת מכירה דמיונית, משכנעת ומופרכת. כל קבוצה מגישה **מוצר אחד בלבד לסבב**, כולל שם, הסבר, מחיר וסלוגן. לאחר מכן נציג אחד מכל קבוצה מוכר אותו בעל פה במשך 30 שניות מול המקרן. הסגל יכול להעלות שאלת ״כרישים״ למסך. הקהל והסגל מדרגים בנפרד.

## מה קורה בכל סבב

### 1. תמכרו לי את זה

- משימה: להמציא מוצר מיותר לחלוטין שקשור לחיים בקמ״ד, ולגרום לסגל להאמין שהוא חיוני.
- ממלאים באתר: שם המוצר, מה הוא עושה, מחיר, סלוגן.
- ההומור מגיע מהניסיון למכור ברצינות משהו שאין בו צורך, לא מסיפור מצחיק שמוכתב מראש.

### 2. הבעיה שלא הייתה קיימת

- משימה: להמציא בעיה מופרכת, כאילו היא בעיה מוכרת בכל קמ״ד, ואז למכור לה פתרון מסובך, יקר או חסר היגיון.
- התיאור חייב לכלול גם את הבעיה וגם את המוצר שמוצע כפתרון.
- כל קבוצה מציגה את העסקה לסגל ומנסה להסביר מדוע היא מצדיקה את המחיר.

### 3. עסקת המאה

- לפני הסבב, חברות הסגל יכולות להזין בטלפון חפץ רגיל אחד כל אחת. כשהסבב מתחיל, המערכת בוחרת חפץ לכל קבוצה ומצמידה לו **מגבלת מכירה אבסורדית**. חפצים חסרים מושלמים אוטומטית ממאגר גיבוי.
- הקבוצות חייבות לשלב גם את החפץ וגם את המגבלה במוצר שלהן.
- מגישים ומציגים כרגיל.

## מה רואים בכל מסך

### חניכים: `/`

1. **כניסה:** סורקים QR שמופיע במקרן ומקלידים קוד חניכים + שם.
2. **חדר המתנה:** רואים את המספר של הקבוצה וחבריה. בלי לחשוף את ההקפצה.
3. **פתיחה:** שם המשחק והמשימה הכללית.
4. **הגשה:** מקבלים אתגר, שעון, טופס מוצר: שם, הסבר, מחיר, סלוגן. בסבב 3 מקבלים גם חפץ ומגבלה.
5. **לאחר הגשה:** כל חברי הקבוצה רואים את המוצר הנעול ושם המגיש. מי שמגיש ראשון קובע עבור כל הקבוצה.
6. **הצגה:** רואים איזו קבוצה על הבמה; הנציג מדבר בעל פה והמוצר על המקרן.
7. **הצבעה:** נותנים ציוני 1–5 לשתי הקבוצות האחרות. הצבעה לקבוצה עצמית חסומה גם בשרת.
8. **תוצאות/סיום:** התוצאות והנימוקים מופיעים על המקרן.

### סגל: `/` עם קוד `18608`

1. **כניסה וטרום משחק:** כל מפקדת נכנסת עם שם. היא יכולה להציע חפץ לסבב האחרון.
2. **בזמן הכנה:** הסגל ממתין בלי לראות תוצרים מוקדם מדי.
3. **בזמן הצגת מוצר:** הסגל רואה את הכרטיס, יכול להקיש על שאלת כרישים מוכנה או להקליד שאלה, ולתת ציון 1–5 עם **נימוק כתוב חובה**. השאלה הראשונה שנשלחת בהצגה תופיע במקרן.
4. **בזמן הצבעה:** ניתן להשלים או לתקן ציונים ונימוקים לכל שלושת המוצרים עד תום החלון.
5. **תוצאות:** המקרן מציג את הניקוד ונימוקים נבחרים.

## מוזיקה

לשים את שלושת הקבצים **בתוך `public/`** בדיוק בשמות:

```
news404-server/
  server.js
  package.json
  public/
    index.html
    join-qr.svg
    Hakpaza.mp3
    Hapaza2.mp3
    Hapaza3.mp3
```

המוזיקה אינה מצורפת לארכיון: צריך להוסיף את קובצי ה־MP3 שלכם.

- מנגנים רק במקרן הראשי (`/#screen`).
- לוחצים על **״הפעל מוזיקה״** במקרן כדי לאשר שמע בדפדפן.
- השיר הראשון הוא `Hakpaza.mp3`; הוא מתחיל חזק יותר ונחלש בהדרגה ל־10% במהלך 7 שניות. שני השירים הבאים מתנגנים ב־10%.
- לאחר השיר השלישי הפלייליסט חוזר לשיר הראשון וממשיך בלופ.
- במהלך חשיפת תוצרים, הצבעות ותוצאות המוזיקה מושהית. היא ממשיכה בסבב ההמצאה הבא.
- אם אחד הקבצים חסר, מופיעה הודעת שגיאה במקרן.

## העלאה ל־GitHub + Render

1. חלצו את ה־ZIP והעלו **את התוכן של `news404-server/`** לשורש המאגר. אם במאגר כבר קיימים `server.js` ו־`public/index.html`, החליפו אותם. אין להוסיף תיקייה מקוננת אם Render מוגדר לתיקיית השורש.
2. העלו בנפרד את שלושת קובצי ה־MP3 לתיקיית `public/`.
3. ב־Render ודאו שפקודת ההפעלה היא `npm start` או `node server.js`.
4. ב־Render הוסיפו משתנה סביבה `ADMIN_PASSWORD` עם סיסמה שאתם בוחרים.
5. הפעילו `Deploy latest commit` ובדקו את `https://kamadphantar-1.onrender.com/api/health`.
6. חברו את המקרן הראשי לכתובת `https://kamadphantar-1.onrender.com/#screen`, הפעילו שמע, ובדקו את כל המצבים לפני הפעילות.

**הערות:** קובץ `join-qr.svg` מכוון לכתובת Render שהוזכרה. אם האתר יעבור לכתובת אחרת, החליפו את ה־QR. מצב המשחק נשמר בזיכרון השרת בלבד; הפעלה מחדש של Render במהלך המשחק מאפסת את ההגשות והנקודות.
